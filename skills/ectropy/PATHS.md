# Hot paths

## Change a guarded repository

1. Enter the repository and read its own instructions.
2. Run `plumb doctor .` first when it carries `plumb.toml`.
3. Read `ectropy.toml`; never infer policy from output alone.
4. Run `ectropy .`, make the smallest coherent change, run it again.
5. Run the repository's complete guard before landing.

## Repair a finding

Repair the structure the law names. `ectropy law NAME` states what that law
refuses and whether it admits a boundary; `ectropy cookbook <entry>` explains a
move when a finding names one. Never suppress a finding merely to restore exit zero,
and never narrow the scan to manufacture a clean result. `ectropy shape` prints
the tree Ectropy judged and `ectropy vocabulary` the living atoms per namespace.

## Configure the scan

`ectropy.toml` owns scan globs, module roots, limits, comment and word policy,
syntax grants and bans, justified boundaries, and vocabulary terms. Unknown
fields, malformed globs, empty boundary reasons, and unknown law names refuse
configuration. Path lists use one dialect: `*` stays within one segment, `**`
crosses segments, and a bare directory names only that directory.

## Operate the skill seat

Use `ectropy skill --help` for the grammar. Managed install, status, and upgrade
accept stable only; replacement requires both the state record and the in-path
marker, and an unowned path refuses. Staging takes a non-stable channel, an
exact version, and a new path ending in `ectropy`, and never reads or writes the
managed ledger.
