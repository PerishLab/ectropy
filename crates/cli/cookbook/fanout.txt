# structure.fanout

## Trigger

The `fanout` law fires on a Rust integration-test directory or an application root.

## Solution

For Rust integration tests, group related cases behind Cargo-native `tests/<group>/main.rs` directories (no `[[test]]` stanzas in `Cargo.toml` unless customizing the harness) and keep shared helpers in `tests/support/mod.rs`. Avoid pairing `tests/<name>.rs` with `tests/<name>/` because each pair consumes two fanout slots for one suite. On web application roots such as `apps/web`, move feature modules under `apps/web/src/` so the root holds only entry configuration, `src/`, and `tests/`. Do not trade directory width for hidden module depth.

## Evidence

Regrouping `tests/` into `tests/<group>/main.rs` across `plumb`, `locus`, and `folio` stayed within `fanout = 10` while reducing compiled test binaries; `ensign/crates/api/tests` hit 10/10 from `foo.rs`+`foo/` double-slot pairs, and `folio/apps/web` hit 10/10 from feature modules placed outside `src/`.

## EXIT

Remove this entry when plumb owns the integration-test grouping shape and its fanout check.
